CONFIRMED FINDINGS
1. deployspec.yml runs backend/migrate.py and ensure_seed_data on deployment.
   It does not invoke the import_leads import routine. There is no dev-client copy
   in the reviewed deployment commands.
2. migrate.py is NOT schema-only:
   - Seeds missing inventory catalog items and room types from repository data.
   - migrate_company_dispatch updates existing lead/job company assignments.
   - catalog_material_cleanup removes pricing material assignments whose catalog
     IDs are absent or deleted in the target database.
   - migrate_movers95_pricing copies Gorilla Haulers East settings into Movers 95,
     replaces its rules/rates/services and deletes/recreates its local routes,
     unless its migration marker already exists. Missing/ambiguous source books
     can also fail deployment.
3. ensure_seed_data creates Gorilla Haulers and an admin account if absent.
   Confirm these are intended production defaults; do not run the full importer.
4. migrate.py alters public_move_access before its create-if-missing block.
   It also assumes existing core tables. Production schema must be inspected;
   this script is not a verified migration from every historical release.
5. Unique indexes for default company and active walkthrough per job may fail
   if existing production rows violate their rules. Check counts before migration.
6. Infrastructure changes run alongside the build, before the Deploy stage.
   A failed build does not mean infrastructure was untouched. The reviewed
   pipeline has no manual approval stage before infrastructure changes.
7. Build runs the frontend production build but no Python regression suite.
8. Deployment updates migrations and individual Lambda functions sequentially;
   this is not an atomic release. Old code must tolerate the migrated schema.
9. Deployment removes a legacy LiveSwitch access-token override once per
   environment. Confirm production OAuth refresh authorization beforehand.
10. Existing dev deployment explicitly enables customer-link sending. The new
    inventory-ready SMS production guard is not a global messaging switch.

DATA POLICY
Preserve all current production customers, jobs, users, uploads, reports and IDs.
Do not restore the dev database over production or run customer import scripts.
Add required tables/columns. Review each backfill separately before enabling it.
Copy configuration only from an explicit reviewed manifest with source/target
company IDs, dependent IDs, row counts and overwrite rules. Candidates: pricing
books, catalog customizations, moving terms, templates, company settings.
Repository catalog seeds do not include all custom records edited in development.
Credentials and OAuth tokens must be configured for production, not bulk copied.
